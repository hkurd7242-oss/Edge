# Edge research notes: low-cost, high-knowledge trading intelligence

Research checked 18 October 2026. Product integrations must be rechecked against live documentation before public/commercial distribution; provider terms and availability change.

## 1. The product problem

A trader doesn't need another screen full of prices. Edge should reduce the time between a meaningful change and a well-formed decision. The decision loop is:

**Observe → verify source → understand catalyst → compare expectations → inspect positioning/flow → estimate execution cost → define invalidation → record outcome → learn.**

An event list without transmission analysis is noise. A token scanner without security/liquidity analysis is dangerous. A large upside target without a plausible probability distribution and controlled downside is not asymmetry. An AI-written narrative that isn't linked to evidence creates confidence, not necessarily knowledge.

## 2. Why the initial build is intentionally cheap

| Capability | Initial source | Marginal provider cost | Important limitation |
|---|---|---:|---|
| DEX pair discovery | DexScreener public API | $0 at current public API surface | Search sampling, rate limits, incomplete token universe |
| Crypto market regime | CoinGecko global endpoint | $0 on a keyless/public call within applicable limits | Demo API has quotas/attribution requirements; not a free unlimited commercial feed |
| Macro calendar | FinanceCalendar public API | $0 | Link attribution required; does not include earnings calendar |
| Primary policy news | Fed, ECB, BOJ RSS | $0 | Feed availability and formats can change |
| Public-company filings | SEC EDGAR RSS/APIs | $0 | Requires a declared User-Agent and fair-use rate discipline |
| Cross-asset reference board | Yahoo Finance public chart endpoint | $0 | Unofficial, may be delayed/blocked/changed; never describe as execution-grade real time |
| Knowledge layer | Curated local lessons | $0 per use | Human-maintained; no live web research is generated by the lesson library |
| Deterministic event explanation | Local rules and templates | $0 per use | Classification is heuristic; direction remains conditional |

The initial release avoids paying for an LLM on every refresh. The product should buy data only where it creates a measurable improvement: missing event coverage, materially better latency, reliable historical data, accurate on-chain entities, or usable execution depth.

## 3. Event intelligence model

### What belongs in the calendar/news layer

- Central-bank decisions, minutes, press conferences and key speeches.
- CPI/PCE/PPI, employment/payrolls, wages, jobless claims, GDP, PMI/ISM, retail sales and consumer activity.
- Treasury auctions, real/nominal yields, curve changes and major financing/liquidity developments.
- Gold, silver, energy inventories, OPEC/supply shocks and industrial-metal demand.
- Major equity earnings, guidance, SEC filings, buybacks, dilution, litigation and regulatory actions.
- Crypto ETF/flow developments, listings, protocol upgrades, exploits, stablecoin stress, exchange incidents and material governance decisions.
- Geopolitics, sanctions, tariffs, conflict, trade policy and supply-chain disruptions.

This coverage is a target, not a claim that one free feed contains every event. Use official source calendars to verify dates and primary releases to verify outcomes. The UI must show provider failures and the source's last update.

### How Edge explains an event

1. **Event type and source reliability:** official release, filing, news report, rumor or secondary commentary.
2. **Timing:** scheduled time, event timestamp and ingestion timestamp; show timezone.
3. **Expectation gap:** actual versus consensus and prior/revisions when the source supplies them. Never invent consensus.
4. **Transmission channel:** rates, real yields, USD, liquidity, earnings/cash flows, energy supply, risk premia, leverage or token-specific demand.
5. **Affected assets:** candidates for research, not guaranteed directions.
6. **Scenario tree:** what would make the reaction positive, negative, mixed or already priced in.
7. **Observed reaction:** price/volume/volatility before and after the event with synchronized timestamps when available.
8. **Outcome review:** record the thesis before the event and evaluate multiple horizons after it.

## 4. Asymmetric research framework

Edge currently builds a research queue, not trade calls. A future validated opportunity model should score independent dimensions separately rather than collapsing them into one magical number:

- **Catalyst quality:** scheduled/confirmed, time-bounded, source verified.
- **Expectation gap:** evidence that consensus or positioning may be wrong; confidence and source disclosed.
- **Transmission clarity:** a defensible mechanism from event to asset cash flows, rates, flows or supply/demand.
- **Independent confirmation:** primary-source evidence plus market/flow/positioning evidence.
- **Tradeability:** spread, depth, slippage estimate, market impact, pool reserves, fees and exit liquidity.
- **Downside definition:** thesis invalidation, gap risk, contract risk, concentration and maximum loss.
- **Payoff asymmetry:** ranges and scenario assumptions, not a single unjustified target.
- **Portfolio interaction:** factor/correlation exposure, funding and concentration.
- **Empirical validation:** event-study sample size, base rate, net expectancy, drawdown, out-of-sample performance and calibration.

A high score should not be shown as a probability unless calibrated against a sufficiently large, point-in-time dataset. For new tokens, contract/holder analysis and exit depth are hard gates, not merely small score penalties.

## 5. How the system should get smarter without expensive AI

- Use rules and structured data for numerical analysis; never ask a language model to invent numeric outputs.
- Cache provider responses by refresh cadence, not by page visit.
- Store raw source metadata, event timestamp, observed timestamp, normalized facts and outcome snapshots.
- Keep a permanent log of every idea as it appeared at decision time; do not rewrite the old thesis after seeing the outcome.
- Add event-study jobs for CPI/FOMC/NFP/EIA and crypto-specific catalysts.
- Compare returns at 15m, 1h, 4h, 1d and 1w where market data supports them; subtract fees, slippage and funding.
- Evaluate the same setup in multiple regimes and asset classes; use a holdout period.
- Track false positives, maximum adverse excursion, maximum favorable excursion, drawdown and tail losses—not just win rate.
- Use a language model only as an optional explanation layer after deterministic calculations, and make the source evidence available beside every claim.

## 6. Staged roadmap

### Stage A — shipped in this package

Mobile-first PWA shell; public data refresh; source-labelled news and event calendar; cross-asset reference board; DEX activity screen; asymmetry research queue; local learning library; risk calculator; paper journal; SQLite caching and watchlist; provider failure transparency.

### Stage B — highest value next

1. Official FRED/ALFRED adapter for real yields, Treasury yields, credit spreads and historical macro series; keep API key in environment and cache aggressively.
2. Direct BLS release-calendar integration and additional official central-bank calendars; cross-check calendar timestamps against primary sources.
3. Event study database with point-in-time actual/consensus/prior and post-event return windows.
4. Better source clustering/deduplication so one event covered by 20 outlets becomes one story with multiple links.
5. Explicit freshness scoring and alerts for source outages, calendar revisions and material events.
6. Gold/FX/energy-specific headlines and supply data, with source and license review.

### Stage C — only after Stage B data quality

1. Wallet cohorts and repeat-performance analytics with realized versus unrealized PnL distinction.
2. Contract security/holder concentration adapter and verified token-address mapping.
3. Order-book/pool-depth slippage estimator and execution feasibility.
4. Backtested signal calibration with confidence intervals and honest base rates.
5. Optional Telegram push alerts; rate-limited and user-configured.

### Stage D — only when paid data is justified

Add licensed real-time market data, premium wallet labels, derivatives/options surfaces, earnings calendars or an LLM narrative layer only when the user can point to a decision-quality gap and measure the benefit. Do not build the cost structure around premium APIs before product-market validation.

## 8. Evidence and honesty boundary

The existence of a provider endpoint proves only that the data may be obtainable—not that the source is always available, timely, complete, licensed for every use, or predictive. This build was syntax-checked and unit-tested offline. The external providers were not live-tested from the build environment. The first live refresh on the VPS must be evaluated through the Provider Status panel and server logs. No profitability claim is made.
